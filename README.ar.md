# ⚒ iForge

### محرك بناء مفتوح المصدر لمشاريع iOS.

---

iForge هو محرك أتمتة مفتوح المصدر مصمم لبناء مشاريع iOS المدعومة من مستودعات GitHub وإنتاج ملف IPA غير موقّع، جاهز للتوقيع باستخدام الأداة التي تختارها.

لا تحتاج إلى إعداد Xcode محليًا.

لا يحتاج iForge إلى حساب Apple Developer.

لا تحتاج إلى شهادات توقيع أو Provisioning Profiles ضمن مسار البناء الأساسي.

فقط أدخل مستودع GitHub، ودع iForge يتولى عملية البناء.

---

## ✨ لماذا iForge؟

بناء مشاريع iOS خارج Xcode قد يكون معقدًا.

كل مشروع يمكن أن يختلف في:

- هيكل المشروع
- Workspaces
- Schemes
- Dependencies
- إعدادات البناء

iForge مصمم لإزالة أكبر قدر ممكن من هذا العمل اليدوي.

مهمته بسيطة:

> **حلّل. اكتشف. ابنِ. صدّر.**

أما التوقيع فهو اختيارك.

## 🎯 فلسفة iForge

يفصل iForge بشكل متعمد بين **البناء** و**التوقيع**.

مسؤولية iForge هي تجهيز التطبيق وبناءه.

أما عملية التوقيع فتبقى خارج المسار الأساسي لـ iForge.

وهذا يسمح للمطور باستخدام أداة التوقيع التي تناسب طريقة عمله.

**iForge يبني. وأنت تختار طريقة التوقيع.**

## ⚡ البدء السريع

iForge يعمل حاليًا من خلال GitHub Actions.

### 1. افتح Actions

افتح تبويب **Actions** داخل مستودع iForge.

### 2. اختر iForge

اختر Workflow:

**iForge**

### 3. تشغيل Workflow

اضغط **Run workflow**.

### 4. أدخل المستودع

أدخل مستودع GitHub بهذا الشكل:

`owner/repository`

مثال:

`iRaay/Navi`

### 5. شغّل iForge

سيقوم iForge بـ:

- استنساخ المستودع
- تحليل المشروع
- اكتشاف Xcode Project أو Workspace
- اكتشاف الـ Schemes
- تجهيز البيئة
- بناء مشروع iOS
- إنشاء Xcode Archive
- إنشاء IPA غير موقّع

### 6. تحميل النتيجة

بعد انتهاء Workflow، افتح الـ Artifacts.

يتم تسمية ملف IPA تلقائيًا بناءً على اسم ملف `.app` الذي تم اكتشافه. على سبيل المثال:

`Navi.app` → `Navi.ipa`

`SimpleApp.app` → `SimpleApp.ipa`

`*.app` → `*.ipa`

أما تطبيق iForge نفسه:

`iForge.app` → `iForge-Build.ipa`

يمكن بعد ذلك توقيع ملف IPA باستخدام أداة التوقيع التي تختارها.

---

## 📱 التوقيع

التوقيع موجود عمدًا خارج المسار الأساسي لـ iForge.

يمكن تمرير ملف IPA غير الموقّع إلى أدوات متوافقة مثل:

- Feather
- AltStore
- Esign
- Sideloadly
- وغيرها من أدوات التوقيع المتوافقة

لا يحتاج iForge إلى شهادة توقيع أو Provisioning Profile لإنشاء ملف IPA غير موقّع.

## 🏗 بنية المشروع

بنية iForge الأساسية:

- `.github/workflows/` — GitHub Actions Workflows
- `scripts/analyze.sh` — تحليل المشروع
- `scripts/prepare.sh` — تجهيز البيئة
- `scripts/build.sh` — بناء وأرشفة مشروع iOS
- `scripts/export.sh` — تصدير IPA غير موقّع
- `templates/` — قوالب البناء المستقبلية
- `plugins/` — نظام الإضافات المستقبلي
- `docs/` — توثيق المشروع

يعتمد المسار الأساسي على مبدأ بسيط:

**Analyze → Prepare → Build → Export**

كل مرحلة لها مسؤولية محددة.

## ⚠️ القيود الحالية

iForge v0.1.0 هو إصدار مستقر مبكر.

يركز الإصدار الحالي على المشاريع التي يمكن تحليلها وبناؤها بنجاح باستخدام أدوات Xcode من سطر الأوامر.

قد تحتاج بعض المشاريع إلى إعدادات إضافية أو Dependencies أو Build Settings لا يتم التعامل معها تلقائيًا بعد.

سيستمر تطوير اكتشاف المشاريع والـ Schemes وتحسينه في الإصدارات القادمة.
